# Go live — The Long Run on Cloudflare Workers

Code is ready (React + TanStack Start + Neon). These are the manual steps only you can do.
Target URL: **`longrun.vanvelzen.dev`**.

---

## 1. Create the Neon database

1. Sign up at <https://neon.tech> with your **personal GitHub** (or personal email — not your work email).
2. Create a project + a database `thelongrun`.
3. Copy the **Pooled connection string** (host contains `-pooler`), e.g.
   ```
   postgres://user:password@ep-xxx-pooler.eu-central-1.aws.neon.tech/thelongrun?sslmode=require
   ```

## 2. Migrate your existing data (local, one time)

```bash
cp .env.example .env       # paste the pooled string as DATABASE_URL
npm install
npm run migrate            # creates tables + loads data/ into Neon
```
Expected: `runs: 40`, `routes: 42`, `context: 8`. Re-running is safe (upserts).

Smoke-test locally — the dev server also reads `DATABASE_URL` from `.env`:
```bash
npm run dev
```
Open the printed URL; the dashboard, maps, splits and Log form should all work against Neon.

## 3. Deploy to Cloudflare

First deploy (from the project root):
```bash
npx wrangler login                                    # once
npx wrangler secret put DATABASE_URL                  # paste the Neon pooled string
npm run deploy                                         # builds + wrangler deploy
```
`npm run deploy` runs `vite build` then `wrangler deploy`; the app name is `the-long-run`
(from `wrangler.jsonc`, with `nodejs_compat` already set). You'll get a `*.workers.dev` URL —
open it and confirm it works.

Optional env: set `DEFAULT_LAT` / `DEFAULT_LON` the same way (`wrangler secret put`, or as plain
vars in the Cloudflare dashboard → the Worker → Settings → Variables).

## 4. Custom domain

Cloudflare dashboard → your Worker → **Settings → Domains & Routes → Add** → `longrun.vanvelzen.dev`.
Since `vanvelzen.dev` is already on Cloudflare, the DNS record is created automatically.

## 5. Lock it to just you (Cloudflare Access)

1. Dashboard → **Zero Trust → Access → Applications → Add → Self-hosted**.
2. Domain: `longrun.vanvelzen.dev`.
3. Policy: **Allow**, include your email. Save.

Now every visitor authenticates as you before the app loads — covering view, edit, and delete.

- **Edit / delete** work as before, now backed by Postgres.
- **Strava sync** (log in, pull latest run) is the planned next step — deferred for now.

## Notes / gotchas

- Always use the **pooled** Neon string (`-pooler`).
- Env is read per-request inside server functions — that's required on Workers; don't move
  `process.env.DATABASE_URL` reads to module scope.
- `.env` (local) and `.dev.vars` are gitignored; never commit the connection string.
- `src/routeTree.gen.ts` is generated by the build and is gitignored.
- The old `data/*.md` / `data/routes/*.json` files stay in the repo as the migration source and
  backup; the running app reads only Neon.
